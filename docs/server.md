# PokeFocus server (F2)

Node + Hono API that owns every player's game state. The browser only sends intents (`POST /api/game/action`); the server runs the rules with the same engine (`src/engine`) through the pure reducer `src/game/actions.ts`, stores the result in PostgreSQL (PGlite in development) and returns the new document. Spec: `docs/F2-plan.md`. Contract: `src/game/protocol.ts`.

## Layout

```
server/
  index.ts            entry: env → database (+ migrations) → app → listen; session cleanup every hour
  app.ts              createApp({ env, db, bus?, limiter?, clock? }) — no I/O, used by tests via app.request()
  env.ts              zod-validated environment
  http.ts             ApiError, body parsing, client IP, cookie helpers, requireAuth middleware
  validation.ts       zod schemas (auth bodies, GameAction discriminated union)
  events.ts           in-memory pub/sub for SSE (keyed by user id)
  rate-limit.ts       in-memory fixed-window limiter
  auth/password.ts    scrypt hashing
  auth/tokens.ts      session tokens, friend codes
  routes/auth.ts      /api/auth/*
  routes/game.ts      /api/game, /api/game/action
  routes/social.ts    /api/friends/*, /api/leaderboard
  routes/events.ts    /api/events (SSE)
  db/schema.ts        Drizzle schema
  db/client.ts        PGlite or postgres-js + migrator
  db/migrations/      generated by drizzle-kit (npm run db:generate)
src/game/actions.ts   applyAction(doc, action, env) — pure reducer (server only)
```

## Running

```bash
npm run dev            # Vite on 5173 + API on 8787 (tsx watch, DEV_TOOLS=1, PGlite in .data/pglite)
npm run dev:server     # API only
npm run dev:client     # Vite only (proxies /api → http://localhost:8787)
npm test               # unit + integration tests (in-memory PGlite)
npm run typecheck      # app, node scripts and server tsconfigs
npm run build          # tsc -b (incl. server) + vite build → dist/
npm start              # production: NODE_ENV=production, serves dist/ and /api from one origin
npm run db:generate    # new migration after editing server/db/schema.ts
docker compose up --build   # PostgreSQL 17 + app on :8787
```

Migrations are applied automatically on startup (`drizzle-orm/*/migrator`), for both drivers. To start over in development, stop the server and delete `.data/`.

## Environment

Loaded from the process environment; `server/index.ts` also reads `.env` if present (see `.env.example`).

| Variable | Default | Meaning |
|---|---|---|
| `NODE_ENV` | `development` | `production` turns on `Secure` cookies, static serving of `dist/`, and forces `DEV_TOOLS=0`. |
| `PORT` | `8787` | HTTP port. |
| `DATABASE_URL` | — | `postgres://…`. When set, PostgreSQL via postgres-js; otherwise embedded PGlite. |
| `PGLITE_DIR` | `.data/pglite` | PGlite directory (`memory://` = in memory). Ignored with `DATABASE_URL`. |
| `APP_ORIGIN` | `http://localhost:5173` | Allowed `Origin`s for non-GET requests, comma-separated. In production: the public URL. |
| `DEV_TOOLS` | `0` | `1` = accept `x-dev-now` / `x-dev-seed` and `dev*` actions. Always `0` in production. |
| `TRUST_PROXY` | `0` | `1` behind a reverse proxy: client IP = last `X-Forwarded-For` hop (rate limits). |
| `STATIC_DIR` | `dist` | Built client served in production (SPA fallback to `index.html`). |

## API notes for the client

All endpoints are under `/api`, JSON in and out, cookie `pf_session`. Errors are `{ error: code }` (sometimes with extra fields).

**Every non-GET request** must send `Origin` (browsers do) from `APP_ORIGIN` and `Content-Type: application/json` — also bodyless ones (`logout`, `DELETE …`, `accept`). Otherwise `403 bad_origin` / `415 json_required`.

| Status | Codes |
|---|---|
| 400 | `invalid_json`, `invalid_body` (+ `fields: string[]`), `invalid_scope`, `invalid_period` |
| 401 | `unauthorized` (no/expired/revoked session), `invalid_credentials` (login: wrong password **or** unknown email) |
| 403 | `bad_origin`, `dev_disabled` (dev action without DEV_TOOLS), `wrong_password` (POST /auth/password) |
| 404 | `not_found`, `unknown_friend_code` |
| 409 | game rule errors (see below), `email_taken`, `cannot_add_self`, `already_friends`, `already_requested`, `too_many_friends` |
| 413 | `body_too_large` (> 64 KB) |
| 415 | `json_required` |
| 429 | `rate_limited` (+ `retryAfter` seconds; also the `Retry-After` header) |

Auth: `POST /auth/register` → 201 `{ user }`; `POST /auth/login` → `{ user }`; `POST /auth/logout` (no session needed) → 204; `POST /auth/logout-all` → 204; `GET/PATCH /auth/me`; `POST /auth/password { current, next }` → 204 (other sessions revoked, current kept); `GET /auth/sessions`; `DELETE /auth/sessions/:id` → 204. `PATCH /auth/me { trainerName }` also renames the trainer inside the game doc (bumps the version, emits `game`).

Game: `GET /game` → `GameSnapshot`; `POST /game/action` with a `GameAction` → `ActionResponse` (`{ doc, version, serverNow, result }`). `serverNow` is the game time used (the dev clock when `x-dev-now` is honored).

- **`createPlayer`** takes no `trainerName`: the server passes the account's trainer name to the reducer (`ActionEnv.trainerName`).
- Reducer error codes (409): engine errors (`session_active`, `invalid_duration`, `empty_team`, `ThrowError`, `ChargeError` incl. the new `already_has_status`, `BoxError`, `UseItemError`, mission errors, `invalid_starter`, `no_active_session`, `invalid_times`) plus `no_player`, `player_exists`, `no_session` (pause/resume/cancel/claim/markNotified without a session, startBreak with no session yet), `paused` (claim while paused), `not_finished` (claim before `endsAt`), `already_finished` (pause after `endsAt`), `no_encounter` (nextWave/finishWaves without waves), `no_break` (endBreak), `already_claimed` (startBreak twice for the same session), `session_active` (startBreak during a session), `session_active_elsewhere` (database already holds an active study session for the user).
- `pause` while paused and `resume` while running are idempotent (200, no change but the version still bumps). `dismissResults` and `skipBreak` always succeed.
- `devFinishNow` is not an action: advance the dev clock (`x-dev-now`) past `timer.endsAt`.
- `claim.devFocusLabel` is ignored unless DEV_TOOLS=1 (then no screenshot labels = "no permission" focus value).
- Week keys are the engine's (`weekKeyOf`: the local Monday, e.g. `2026-11-02`), month keys `2026-11`.

Friends: `GET /friends` → `{ friends: FriendSummary[] }` (accepted + incoming + outgoing, oldest first); `POST /friends/request { friendCode }` → 201 `{ userId, status: 'outgoing' | 'friend' }` (code is case-insensitive, spaces/dashes ignored; an inverse pending request is accepted directly); `POST /friends/:userId/accept` → 204 (only the addressee); `DELETE /friends/:userId` → 204 (reject, cancel or unfriend).

Leaderboard: `GET /leaderboard?scope=global|country|friends&period=week|month` → `LeaderboardResponse`. Only rows with points > 0. Ties share a rank (competition ranking: 1, 2, 2, 4), listed by who reached the score first. `mine` is null when the caller has no points in that period.

### Server-Sent Events

`GET /api/events` (use `new EventSource('/api/events')`; same-origin, the cookie goes along). Each event is an unnamed message (`onmessage`) whose `data` is a JSON `ServerEvent`:

- `{ type: 'game', version }` after every successful write of the user's doc (from any tab, including the one that made it — compare `version` and ignore what you already have).
- `{ type: 'friends' }` to both users on request / accept / remove.
- `{ type: 'logout' }` to the connections of a revoked session (logout-all, password change, DELETE /auth/sessions/:id), then the stream closes.

The stream starts with `retry: 5000` and sends a `: ping` comment every 25 s. 401 if there is no session.

## Security

- **Passwords**: `crypto.scrypt` N=2^15, r=8, p=1, 64-byte key, 16-byte random salt, stored as `scrypt$N$r$p$salt_b64$hash_b64`, compared with `timingSafeEqual` (maxmem raised to 64 MiB because N·r·128 = 32 MiB hits Node's default). 8–128 chars, NFKC-normalized. Never logged.
- **No account enumeration on login**: unknown emails are verified against a random dummy hash, same error `invalid_credentials`. (Registration does say `email_taken`; it is rate-limited.)
- **Sessions**: 32 random bytes (base64url) in the cookie, only `sha256(token)` in `auth_sessions`. New token on every login/registration. Cookie `pf_session`: `HttpOnly; SameSite=Lax; Path=/; Max-Age=30d`, `Secure` in production. Sliding expiry: a request more than 24 h after `last_seen_at` pushes `expires_at` to now + 30 d and re-sends the cookie. Expired rows are deleted hourly.
- **CSRF**: `Origin` must be in `APP_ORIGIN` for every non-GET/HEAD request, JSON content type required, plus `SameSite=Lax`.
- **Brute force**: in-memory fixed windows — login 10 / 15 min per IP and 5 / 15 min per email (attempts; a successful login clears the email counter), register 5 / h per IP. Single process only; behind a proxy set `TRUST_PROXY=1`.
- **Authority**: time, rolls, points and captures are decided by the server. `x-dev-now` / `x-dev-seed` and `dev*` actions only with `DEV_TOOLS=1`, never in production.
- **Concurrency**: every action runs in one transaction: `SELECT … FOR UPDATE` on `player_docs` → `applyAction` → `active_study_sessions` / `league_scores` updates → `version + 1`. Two tabs never overwrite each other.
- **Headers**: Hono `secureHeaders()` (HSTS, nosniff, frame options, COOP/CORP, no referrer…). Body limit 64 KB. All SQL through Drizzle (parameterized).

## HTTPS in production

Cookies are `Secure` in production, so the site must be served over HTTPS (browsers do accept Secure cookies on `http://localhost` for local tests). Put a reverse proxy in front of the app; with [Caddy](https://caddyserver.com) (automatic Let's Encrypt certificates):

```caddyfile
pokefocus.example.com {
	encode zstd gzip
	reverse_proxy localhost:8787 {
		# SSE: send events right away
		flush_interval -1
	}
}
```

Then run the app with `APP_ORIGIN=https://pokefocus.example.com` and `TRUST_PROXY=1` (and do not publish port 8787 to the internet: bind it to `127.0.0.1:8787:8787` in `docker-compose.yml` or put Caddy in the same compose network).

## Limits / future work

- The event bus and the rate limiter live in memory: run a single instance (or move them to Postgres `LISTEN/NOTIFY` / Redis).
- No email verification or password reset yet (no mail sending).
